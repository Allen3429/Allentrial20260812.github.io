# DealPause 165｜第一輪真實需求驗證

## 最新需求訊號（2026/9/14）
- 數位產業署 2026/9/10 公布 8/30–9/5 週快訊：37,405 件疑似詐騙通報，25,293 件確認為詐騙，較前週增加 4.96%。
- Meta 佔本週通報 92.02%。
- 詐騙廣告類型以「產品服務」35.60%居首。
- 高風險關鍵字包含「超殺優惠」「團購+1」，常以低價生活用品導向一頁式詐騙網站／不明連結。
- 2026/9/3 警方提醒近期「免費送書包」「歇業倒閉」「拆夥出清」等假優惠，會導向假客服 LINE，再用「超商實名認證」「退款」「系統異常」要求操作 ATM／網銀。
- 165 打詐儀錶板已有 AI 即時防詐諮詢與涉詐網址查證。
- 數發部網路詐騙通報查詢網可通報疑似詐騙並追蹤處理。

## 具體痛點
1. 使用者知道「不要被騙」，但在限時／低價／免費情境下仍會先私訊或點連結。
2. 很多人把「留言很多、粉專看起來像品牌」當可信證據。
3. 一旦被導到 LINE，後續「實名認證／退款／系統異常」話術容易讓人合理化金融操作。
4. 網路上常見工具直接判定「安全／詐騙」，但低誤判要求高；本MVP只做流程風險與官方查證，不假裝能確診。
5. 可疑網址常帶個人 token／訂單參數，不適合直接公開貼在社群。
6. 已轉帳的人需要的是立即停止二次操作、保存紀錄與求助，不是再做更多心理測驗。

## MVP
- 5階段分流：只看到／已點／已加LINE／已輸入敏感資料／已付款。
- 6項紅旗 checklist。
- URL 僅本機解析網域，不上傳、不自動「判定」。
- 165 打詐儀錶板與網路詐騙通報查詢網直連。
- 已付款者直接顯示求助流程。
- 一鍵產生品牌官方查證訊息。
- 私人防詐紀錄卡。
- Public Good Lab 匿名採用量測＋Issue #158。

## 第一輪硬門檻
- 100 位獨立瀏覽器
- 60 人完成一次風險分流
- 40 人點進 165 打詐儀錶板／網址查證
- 25 人在原本準備私訊、加 LINE 或下單前停止一步並改走品牌官方管道查證
- 10 人成功辨識「實名認證／退款／系統異常 → 要求 ATM／網銀」並停止操作
- 5 人回報原本誤以為「免費送／歇業出清」只要看留言多就可信
- 至少 5 個可重複摩擦點

## 測試案例
1. stage=seen, 0紅旗 → 顯示「低分不等於安全」，不宣稱安全。
2. 勾 r4（系統異常／退款） → 直接進高危險紅旗。
3. 勾 r6（ATM／網銀） → 直接進高危險紅旗。
4. stage=paid → 顯示立即聯繫金融機構＋165／110。
5. URL=https://brand.example/order?token=secret → 只顯示 brand.example，不把 query 寫進紀錄卡。
6. URL=https://user@evil.example/path → 顯示 evil.example 並提醒 @ 字元風險。
7. URL 無法解析 → 不嘗試自動開啟，要求改走品牌官網。
8. 不提供任何 URL → 仍能完成整套分流。

## 隱私
公開回饋不要貼銀行帳號、卡號、帳密、OTP、身分證、電話、住址、完整交易明細；若網址帶個人 token／訂單參數，不要原樣公開。
